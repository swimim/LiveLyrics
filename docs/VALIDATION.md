## 사용자 실기기 확인 순서

1. 메뉴바 따옴표 아이콘에서 **오프라인 데모** 공급자를 선택한다. 외부 음악과 별개인 합성 가사임을 확인한다.
2. 오른쪽 위 1/8 영역이 투명하고 가사가 보이지 않는 상태에서 커서를 올려 가사와 안내 문구가 나타나는지 확인한다. 가사 뒤의 앱을 클릭/입력한다.
3. 첫 타임스탬프 전부터 첫 줄이 회색으로 보이고 영역 위에서 시작하는지, 이후 현재 줄이 중앙에 도달한 뒤 중앙에 정착하는지 확인한다. 21.5초 긴 문장, 27초 두 줄, 32–35초 빈 구간을 확인한다.
4. 데모의 멈춤/재개·8초 앞뒤 이동을 반복한다. 역방향 탐색은 즉시 배치되어야 한다.
5. 메뉴의 **가사 잠금**을 켜면 커서가 영역을 벗어나도 가사가 남고, 끄면 벗어날 때 사라지는지 확인한다. 상태 안내 문구는 잠금과 관계없이 hover 중에만 보여야 한다. 가사 표시를 메뉴에서 켰다 끈다. 공급자를 바꾼 뒤 다시 연결한다.
6. 손쉬운 사용의 동작 줄이기가 활성화된 환경에서 슬라이딩이 생략되는지 확인한다.
7. 실제 프로젝트 URL 또는 연락 이메일을 저장한 후 Spotify 곡 3개 이상에서 가사 동기화를 확인한다.
8. 곡 변경 10회, 정지/재개 5회, 앞뒤 탐색 각 5회, 플레이어 재실행, 네트워크 단절/복구, 잠자기/복귀를 확인한다.
9. 오버레이 표시/숨김 20회, 화면 연결/해제, 30분 실행 후 Instruments에서 메모리·CPU·프로세스 수를 기록한다.

## 남은 검증과 알려진 제한

- 1pt 중앙 오차, 200ms 경계 강조 목표, 240ms 미만 cue 연속 전환 및 실제 전환 방향/깜빡임: 미측정.
- 전체 화면/여러 Space/다중 모니터/Retina 배율/Intel: 미검증.
- CPU·메모리 정량 성능 및 30분 안정성 측정: 미실행. 수치를 추정해 기록하지 않음.
- Spotify 길이 단위는 설치본의 사전 설명과 알려진 버전 차이를 확정할 실재생 검증이 없어 생략. 위치는 초로 처리. 길이 미상은 `—:—`로 표시.
- 현재 cue가 영역보다 긴 경우 최소 크기까지 자동 축소하는 대신 줄 수를 제한해 중앙 생략한다. 전체 텍스트는 설정에서 확인 가능.
- 전체 cue VStack은 파서 상한 10,000에서 렌더링 비용이 클 수 있다. 일반적인 곡을 위한 MVP이며 매우 긴 자막 용도로 최적화되지 않았다.
- MediaRemote 실패 시 자동으로 권한 요청을 연쇄 실행하지 않는다. 명시적인 공급자 선택을 제공하며 이 환경 기본값은 Spotify다.

## 패키징 주의점

Desktop 동기화가 생성된 .app/.framework에 `com.apple.FinderInfo`를 다시 붙여 빌드 직후 이후 `codesign --verify --strict`가 실패하는 것을 관찰했다. 원본 소스나 실행 파일의 컴파일 오류는 아니다. 빌드 스크립트는 `/private/tmp`에서 서명하고 ZIP 생성 → 재추출 → strict 서명 검증 후 산출물을 복사한다. ZIP은 동기화 메타데이터가 내부 앱에 붙지 않는 검증된 보관본이다. Desktop의 .app 직접 복사본에 대한 영구적인 strict 서명 통과는 보장하지 않는다.
